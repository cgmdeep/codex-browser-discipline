# Codex Browser Discipline

让 Codex 不只是“会点网页”，而是能够理解用户意图、交互逻辑、页面状态和操作后果。

`codex-browser-discipline` 是一套面向 Codex Browser 与 Computer Use 的网页操作和 UX 评审方法。它把注意力从“控件有没有被点击”提升到“用户的真实目标是否成立”：对象是否正确、范围是否清楚、跳转是否符合预期、结果能否核验，以及失败后能否安全恢复。

## 它解决什么问题

常见网页自动化容易把下面这条链路误认为任务完成：

```text
找到控件 → 点击 → 页面变化 → 成功
```

但页面变化只能证明机制运行，不能证明用户目标成立。例如：

- 点击成功，却进入了错误对象或错误账户；
- 搜索完成，但返回后筛选条件和滚动位置丢失；
- 仪表盘数字更新，却没有单位、时间范围或数据来源；
- AI 任务显示完成，但结果还没有被核验；
- 删除或权限确认框存在，却遗漏关联页面、自动化和下游受众；
- 对话框可以关闭，但键盘焦点没有回到原来的工作位置。

这个 Skill 使用更完整的任务闭环：

```text
理解目标
→ 确认情境、对象和范围
→ 预测行动与后果
→ 操作
→ 验证语义结果
→ 继续、修正、撤销、重试、补偿或停止
```

## 能达到的效果

### 更可靠的网页操作

- 核对账户、工作区、对象、筛选范围和权限。
- 根据角色、名称、状态和上下文选择正确控件。
- 操作后验证实际对象和目的地，而不只相信 toast、URL 或动画。
- 遇到失败时先诊断遮挡、焦点、验证、加载和状态问题，避免盲目重复点击。
- 在发送、发布、支付、授权和删除前识别真正的承诺边界。

### 更接近真实用户的 UX 评审

- 检查视觉层级、阅读起点、控件分组、操作距离和信息密度。
- 验证点击跳转、浏览器返回、筛选保留和上下文连续性。
- 检查键盘焦点、触控替代、悬停解释与辅助技术语义。
- 区分可观测失败、强可用性问题、设计假设和正向发现。
- 优先修复用户任务中最早断裂的一环，而不是罗列组件问题。

### 对复杂界面的迁移能力

- 仪表盘：区分数值显示、指标解释和决策支持。
- 表格与编辑器：分别追踪模式、选择、视点、历史和持久化。
- AI 与自动化：分离执行状态和结果权威性。
- 高风险流程：检查对象、范围、账户、受众、依赖对象、后果和恢复路径。
- 陌生界面：根据人的认知任务分析，不依赖页面类型清单。

## 核心优势

1. **不依赖页面类型**：把 CRM、后台、商城、地图、知识库和 AI 工作台还原为定位、理解、输入、比较、操作、等待、承诺和恢复等人的任务。
2. **语义成功高于形式成功**：区分按钮被点击、界面变化、系统状态变化和用户目标真正成立。
3. **人体工学与交互逻辑并重**：既检查布局和操作成本，也检查跳转、状态、反馈和恢复是否符合人的预期。
4. **对高风险操作保持克制**：根据后果选择验证深度，在没有授权或证据不足时停在最终提交之前。
5. **结论可复核**：分开记录观察证据、判断类别、优先级和未测边界，避免把个人审美包装成事实。
6. **按需加载**：主 Skill 保留通用执行循环，表单、数据界面、异步 AI 和正式评审规则分别存放在参考文件中。

## 适用与不适用

适用于：网页操作、交互设计评审、渲染后前端验证、表单和发布流程、仪表盘、编辑器、AI 工作台及高风险确认流程。

不适用于：仅做网络搜索、只调用 HTTP/API、没有运行界面的纯代码审查，或需要法律、医疗、金融等专业领域结论的任务。

当前版本按 v0.2 冻结，已跨搜索、表单、仪表盘、表格、画布、AI 工作台以及 GitHub 删除和权限流程验证。测试范围、实际发现与未覆盖边界见 [VALIDATION.md](VALIDATION.md)。

它证明了该方法已经能够稳定改善 Codex 的观察、操作、核验和停止决策，但不声称替代真实用户研究、业务规则或所有辅助技术测试。
